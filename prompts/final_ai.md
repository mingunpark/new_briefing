# Daily AI Briefing (v3)

오늘의 AI·오픈소스 트렌드 브리핑을 작성해서 Slack `#daily-news` 에 전송해줘.
투자 브리핑은 별도 작업이 담당하므로 이 작업에서는 다루지 않는다.

## 0. 공통 실행 규칙 (모든 섹션에 우선 적용)

### 0-1. 날짜
- 시작하자마자 `TZ=Asia/Seoul date` 로 현재 KST 시각을 확정하고, 첫 메시지 최상단에
  `📅 YYYY-MM-DD (요일) HH:MM KST 기준` 을 표기한다.
- 검색어에는 "오늘/today" 대신 실제 날짜 문자열을 넣는다. (예: `AI news October 28 2026`)

### 0-2. 데이터 수집 순서 (중요)
1. **수집 데이터 파일을 먼저 읽는다.**
   `curl -s https://raw.githubusercontent.com/mingunpark/new_briefing/main/data/latest.json`
   - 파일을 못 읽거나(404 등) `generated_at_utc` 가 지금보다 **12시간 이상 오래됐으면** 파일 전체를 쓰지 말고 2단계로 간다.
   - `failed_sources` 에 있는 항목만 2단계로 직접 수집한다.
   - 파일 값은 `[확인됨]` 으로 쓰되, 출처는 파일 안의 `source` 와 `as_of`/`record_date` 를 그대로 옮긴다.
2. **직접 API 호출** (curl). 허용된 도메인: api.fiscaldata.treasury.gov, fred.stlouisfed.org,
   home.treasury.gov, huggingface.co, hn.algolia.com, query1.finance.yahoo.com, api.github.com
3. 그래도 실패하면 WebFetch / WebSearch 로 1차 출처를 찾는다.
4. 모두 실패하면 `❌ 확인 실패 (시도한 출처: …, 사유: …)` 로 남긴다.

**금지**: 출처 없는 값을 `~`, `약`, `추정` 같은 근사치로 채우기. 숫자는 출처가 있는 값만 쓴다.
(예외: 원화 환산·용량처럼 출처 값으로 직접 계산한 값은 `≈` 로 표기할 수 있다)
네트워크 오류가 나면 같은 URL을 반복하지 말고 다음 단계로 넘어간다.

### 0-3. 사실 검증
- 모든 수치·사실에 ① 출처 ② 기준 시각을 붙인다. 예: `10Y 4.99% (US Treasury Par Yield, 10-27)`
- 핵심 수치는 서로 다른 2개 출처로 교차검증한다. 다르면 둘 다 적고 `⚠️ 출처 불일치` 표기.
- 신뢰도 라벨: `[확인됨]` / `[아마도]` / `[미검증]`
- 항목 수를 채우려고 오래된 뉴스나 유명 프로젝트로 빈칸을 메우지 않는다. 부족하면 "오늘은 N건"이라고 밝힌다.

### 0-4. 중복 방지 (Slack 기록 기반)
- 로컬 파일은 실행 사이에 남지 않으므로 사용하지 않는다.
- 작성 전에 Slack `#daily-news`(채널 ID `C0AVBCP4QK0`)의 **최근 7일 메시지**를 읽어
  이미 다룬 키워드·레포·모델·뉴스를 목록으로 만든다.
- 이미 다룬 항목은 제외한다. 단, 중대한 후속 전개가 있으면 `🔄 후속` 태그로 재등장을 허용한다.

### 0-5. Slack 전송
- 채널: `#daily-news` (`C0AVBCP4QK0`), Slack 커넥터의 메시지 전송 도구를 사용한다.
- mrkdwn 문법: 굵게 `*텍스트*`, 링크 `<https://url|텍스트>`. `**`, `#` 헤더, 표는 쓰지 않는다.
- 메시지 1개는 3,000자 이내로 나눠 보낸다. 전송 실패 시 1회 재시도하고, 그래도 실패하면 에러를 출력한다.

### 0-6. 가독성 (강제)
- 첫 메시지 맨 위에 `⚡ 오늘의 3줄`. 이것만 읽어도 흐름이 잡혀야 한다.
- 각 항목은 첫 줄 = 결론, 그 아래 = 근거 (역피라미드).
- 한 문장 60자 이내, 한 문단 3줄 이내, 한 항목 8줄 이내, 불릿 1개는 1줄.
- 늘어지는 어미(`~라고 할 수 있다`, `~인 것으로 보인다`) 대신 `~다`로 끊는다.
- 구조용 이모지만 쓰고, 문단당 1개 이하. 구분선은 `━━━━━━━━━━━━━━━` 로 통일한다.
- 전문용어는 첫 등장 1회만 괄호로 풀어 쓴다. 근거 없는 수식어(혁신적, 게임체인저, 주목받는)는 금지.
- 항목 사이에는 빈 줄 1개를 넣는다.

## 1. 후보 수집 (작성 전에 반드시 이 순서로)

`latest.json` 의 `ai` 섹션을 기본 재료로 쓴다.
- `github_star_velocity`: 어제 대비 star 증가량 (가장 중요한 신호)
- `github_trending_daily`: GitHub trending 의 `stars_today`
- `github_new_repos_45d`: 최근 45일 내 생성된 레포 (star 순)
- `hn_top_24h`, `reddit_top_day`, `hf_trending`, `hf_daily_papers`

그 다음 WebSearch 로 최근 48시간 AI 뉴스(공식 블로그, TechCrunch, The Verge, VentureBeat)를 보강한다.

### 1-1. "놓치면 안 되는 항목" 강제 점검 ★
아래 중 하나라도 해당하면 **반드시 후보에 올리고**, 제외할 거면 제외 사유를 한 줄로 남긴다.
- `gain_since_prev` ≥ 1,000 이거나 `stars_today` ≥ 1,000 인 레포
- 생성 60일 이내인데 총 star 가 10,000 이상인 레포 (바이럴 신호)
- HN 24시간 300pt 이상 스토리
- 2개 이상의 소스(GitHub / HN / Reddit / HF / 주요 매체)에 동시에 등장한 이름

### 1-2. 채택 규칙: 교차 신호
- 후보는 **서로 다른 소스 2곳 이상**에서 확인될 때 채택한다.
- 1곳에서만 보이는데 증가세가 압도적이면 `[아마도]` 라벨로 채택할 수 있다.

### 1-3. 제외 규칙 (총 star 수로는 제외하지 않는다)
- 최초 등장 후 60일 이상 지났고 이미 공식 문서·위키가 정착된 개념
- 최근 7일 Slack 기록에 이미 나온 항목 (0-4 규칙)
- awesome-*, *-roadmap, 면접질문 모음 같은 큐레이션 리스트
- 기술적 신규성이 없는 단순 리브랜딩
- star 조작 의심: `forks` 가 star 의 1% 미만이고 다른 소스(HN·Reddit·매체)에 언급이 없는 레포

> 이전 버전의 "총 star 20k 이상 제외" 규칙은 폐기됐다. 며칠 만에 수만 star 를 얻은 바이럴 프로젝트(예: REA)를
> 놓치는 원인이었다. 유명한지 여부는 **star 총량이 아니라 최초 등장 시점**으로 판단한다.

## PART 1. 🤖 AI 트렌드

### [🔥 오늘의 AI 버즈] — 3~5개
각 항목:
1. 한줄 개념 설명 (비전공자 기준)
2. 왜 지금 뜨나 — 언제부터, 어떤 계기로. 숫자 근거 (star 증가량, HN 포인트, Reddit 점수, arXiv 번호)
3. 활용 예시
4. `🏦 사내 적용` — 폐쇄망·금융권에서 쓸 수 있는지 한 줄

### [📰 AI 주요 뉴스] — 3건
- 최근 24시간 우선, 부족하면 48시간까지 (`(48h)` 표기)
- 1차 출처(공식 블로그, 논문, 공시) 우선. 기사만 있으면 2개 매체 교차 확인
- 각 뉴스: 팩트(누가/언제/무엇) + 링크 → 의미 → 주목 이유

### [⭐ GitHub 급상승 오픈소스] — 5개
- 정렬 기준: `gain_since_prev` → `stars_today` → 생성일 최신순
- 각 항목: 레포 링크, 한줄 설명, 왜 뜨나, `오늘 +N★ / 총 N★`, 라이선스,
  `🏦 폐쇄망 적용도` ⭕ 가능 / 🔺 조건부 / ❌ 불가 + 한 줄 사유 (외부 API 의존, SaaS 전제, 라이선스)

## PART 2. 🤗 Hugging Face 급상승

GitHub 섹션과 같은 프로젝트는 한쪽에서만 다룬다.
재료: `ai.hf_trending` (model / dataset / space), `ai.hf_daily_papers`.
파일에 없으면 `https://huggingface.co/api/trending?type=model` 등을 직접 호출한다.

### 필터링 (트렌딩 순위를 그대로 옮기지 않는다)
**우선순위 A (최소 3개)**
- LLM, 특히 경량·양자화 모델 (GGUF/AWQ/GPTQ)
- 임베딩 / 리랭커 / 한국어 지원 모델
- Agent·Tool-use·함수호출 특화 모델
- 문서 파싱, OCR, 표 추출
- 시계열, 정형데이터(tabular) 모델
- 코드 생성·리뷰 모델

**우선순위 B (최대 2개)**: 이미지·영상·음성 생성. 업계 흐름상 의미를 설명할 수 있을 때만.

**무조건 제외**: 단순 미러·재업로드, `runtime_stage` 가 RUNNING 이 아닌 Space, 최근 7일 내 다룬 항목.

### 각 항목 (3~5개)
1. 이름 + 링크 + `[모델]/[데이터셋]/[Space]/[논문]`
2. 한줄 설명 (비전공자 기준)
3. 왜 지금 뜨나 — likes, 신규 여부(`created_at`), 연결된 논문·발표
4. 체험 방법 — Space URL 또는 짧은 코드
5. `🏦 폐쇄망 반입 카드` (표 대신 줄로)
   `라이선스: … / 크기: …B, ≈…GB / 반입: hf download {id} / 오프라인: ⭕🔺❌ / GPU: …` + 판정 근거 한 줄
6. `💡 연결점` — LangGraph4j 에이전트 플랫폼, Dataiku 파이프라인 중 어디에 붙일 수 있는지.
   없으면 "직접 연결점 없음"이라고 쓴다.

## 2. 전송 순서와 형식

메시지 1: `📅 날짜` + `⚡ 오늘의 3줄` (AI 버즈 / GitHub / HF 각 1줄) + PART 1
메시지 2: PART 2
메시지 마지막 줄: `_데이터: new_briefing latest.json (생성 {generated_at_kst}) · 실패 소스: {failed_sources 또는 없음}_`

항목 골격:
```
*1. {이름}* [신규] ⭕폐쇄망가능 [확인됨]
  → 한줄 설명
  • 왜 뜨나: {계기} ({날짜}, {숫자 근거})
  • 쓸 곳: {활용 예시}
  • 🏦 {사내 적용 한 줄}
  <링크|자세히>
```
